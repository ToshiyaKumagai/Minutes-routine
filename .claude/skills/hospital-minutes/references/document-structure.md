# 議事録の構成と編集方針

## セクションの選び方

固定の目次はない。素材に実際に含まれていた話題だけを立てる。空のセクションを作らない。

会議の種類ごとに立ちやすいセクションの目安：

**キックオフ・部門別キックオフ**
1. 全体スケジュール
2. 会議体と今後の進め方（運用検討部会／操作研修／リハーサル／部会の新設）
3. データ移行
4. 個別論点（部門固有の話題を h2 で並べる）
5. 先行着手のお願い（数値評価レビュー等、期限付きの依頼がある場合）
6. コミュニケーション・情報共有

**運用検討部会・病棟部会**
1. 前回からの申し送り
2. 決定事項
3. 保留・持ち帰り事項
4. 次回に向けて

**ヒアリング**
1. 現状の運用
2. Henry での実現方法
3. 確認が必要な点

番号は「1.」「2.」と連番、小見出しは「4-1.」「4-2.」の形式にする。セクションを削ったら必ず番号を振り直す。

## ToDo一覧・継続検討事項について

**標準では入れない。** 依頼事項は送付メール本文に「ご依頼事項」として書くほうが相手の目に留まりやすく、議事録側に重複して置くと、どちらが正なのか分からなくなる。

利用者から明示的に「ToDo表も入れて」と言われたときだけ追加する。その場合は No. / 内容 / 期限の目安 / 備考 の4列で、病院様分とヘンリー分を分ける。

## 編集方針

素材は録音の文字起こしと AI 要約であることが多い。そのままでは顧客に出せないので、次の観点で書き直す。

**話し言葉を書き言葉に。** 「〜ですね」「ちょっと」「〜みたいな感じで」を落とし、敬体で整える。病院側の行動には「ご確認ください」「お願いいたします」、自社の行動には「いたします」「ご案内します」を使う。

**発言の順ではなく論点でまとめる。** 会議では同じ話題が何度も戻ってくる。時系列に並べず、論点ごとに集約する。

**決まったことと決まっていないことを書き分ける。** 「〜で確定しました」と「〜を検討します」「現時点では未確認です」を混ぜない。素材が曖昧なときは断定せず、曖昧なまま書く。憶測で補完しない。

**数字・期限・固有名詞は素材から取る。** 日付、期間、機能名、システム名は文字起こしの記載をそのまま使う。素材にない期限を勝手に置かない。

**背景と理由を残す。** 「なぜ先行して着手するのか」「なぜこの運用を推奨するのか」は、院内で共有されたときに効いてくる。結論だけに削らない。

**未確定事項は「継続して確認します」と明示する。** 会議で答えられなかったことを黙って落とすと、後で認識の相違になる。

## 個人名の扱い

**病院側の担当者名は書かない。** 「看護部ご担当者様」「医事課ご担当者様」のように役割で表す。出席者欄も同様。顧客の個人情報を成果物に残さないため。医療機関名は書いてよい。

**自社（ヘンリー）側のメンバー名は書く。** 出席者欄に「熊谷（運用窓口・プロジェクト推進）」のように役割を添えて記載する。誰に聞けばよいかが分かるほうが病院側の役に立つ。

素材によって担当者の記載が食い違うことがある（Notion の要約と文字起こしで名前が違う等）。その場合は文字起こしを優先し、食い違いがあったことを利用者に伝えて確認を促す。

## AI作成の注記

表紙の会議情報テーブル直下に【ご確認のお願い】ボックスを必ず置く（`ai_notice`）。内容は、①録音をもとに AI で作成し担当者が編集したものであること、②聞き取り誤りや認識の相違が含まれる可能性、③誤りがあれば指摘してほしいこと、④指摘を受けたらすみやかに修正して再共有すること。

④まで書くのが大事。免責だけを並べると「間違っていても知らない」という読まれ方をする。直す前提であることを示す。

同じ趣旨をメール本文にも入れる。添付を開く前に前提が伝わるよう、添付資料一覧より前に置く。
