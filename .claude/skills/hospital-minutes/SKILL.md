# 病院向け議事録作成

病院への電子カルテ導入プロジェクトで、会議の素材（Notion のメモ、Google ドキュメントの AI 要約、録音の文字起こし）から、顧客にそのまま渡せる議事録と送付メールを作る。

素材はたいてい話し言葉のままで、同じ話題が会議中に何度も行き来している。それを論点ごとに整理し、決まったことと決まっていないことを書き分け、院内で回覧される前提の文章に直すのがこのスキルの仕事。

## 進め方

### 1. 素材を全部読む

利用者が渡してくるものは複数あることが多い。URL が示されたら開き、添付ファイルがあれば読む。

- Notion ページ → `Notion:notion-fetch`
- Google ドキュメント → `Google Drive:read_file_content`
- 添付の Excel / PDF → 該当スキル（xlsx / pdf-reading）を先に読んでから開く

同じ会議について複数の素材があるときは、**文字起こしを一次情報として扱う。** AI 要約は要点を掴むのに使い、事実関係が食い違ったら文字起こしを取る。食い違いに気づいたら、あとで利用者に伝える。

同じ日の別の会議（部門別キックオフとその後のヒアリング等）が素材にあるなら、1つの文書にまとめてよい。依頼事項の背景がつながって読みやすくなる。

### 2. 構成を決めて本文を書く

`references/document-structure.md` を読む。セクションの選び方、話し言葉の直し方、個人名の扱い、AI 作成注記の書き方が書いてある。

特に外さないでほしいのは次の3点。

**病院側の担当者名は書かない。** 「看護部ご担当者様」のように役割で表す。医療機関名は書いてよい。自社メンバーの名前は役割を添えて書く。

**ToDo一覧・継続検討事項のセクションは標準では作らない。** 依頼事項はメール本文に書く。明示的に頼まれたときだけ議事録にも入れる。

**AI 作成の注記を必ず入れる。** 表紙の会議情報テーブル直下と、メール本文の両方に。

### 3. content.json を書いて Word を生成

書式（色・フォント・余白・改ページ制御）は `scripts/build_minutes.js` に固定してある。本文の中身だけを JSON で書く。

```bash
node scripts/build_minutes.js content.json "20260812_○○病院様_会議名_議事録.docx"
```

JSON の形式は `references/content-schema.md` を参照。ブロック種別は `h2` / `bullet` / `para` / `note` / `link` の5つだけ。

`docx` パッケージが見つからないときは `npm i -g docx --prefix ~/.npm-global` で入れる。

### 4. PDF に変換して、目で確認する

```bash
python /mnt/skills/public/docx/scripts/office/soffice.py --headless --convert-to pdf "<出力.docx>"
pdftoppm -jpeg -r 90 "<出力.pdf>" page
```

生成した `page-*.jpg` を `view` で実際に見る。テキストが正しく入っているかではなく、**レイアウトが崩れていないか**を見る。よくあるのは、見出しがページ末尾に取り残される、表がページ境界で割れる、最終ページが1行だけになる、あたり。番号を振り直したのに本文中の参照が古いまま、というのもここで見つかる。

Word と PDF の両方を成果物として渡す。

### 5. 送付メール文面を作る

`references/email-template.md` を読み、`message_compose_v1` で提示する。件名・宛名・AI 作成の注記・添付資料一覧・番号付きのご依頼事項、という構成。

依頼事項は利用者が口頭で挙げていることが多い。番号付きで整理し、それぞれに「何を・どう・いつまでに」を1〜3行で添える。期限があるなら理由も書く。

メールアドレスは本文に書かない。宛先本人のものであっても「本メールの宛先アドレス宛に」と表現する。

### 6. 気づいたことを伝える

素材を読んでいると、利用者に確認したほうがよいことが出てくる。まとめて伝える。

- 素材間で食い違っていた点（担当者名、日付、数字）
- 音声入力の変換ミスと思われる箇所（「介護計画」→「看護計画」など）。こちらの判断で直したなら、直したことを言う
- 出席者欄など、送付前に埋める必要がある箇所

## 成果物

- `YYYYMMDD_○○病院様_会議名_議事録.docx`
- 同名の `.pdf`
- 送付メール文面（`message_compose_v1`）

docx と pdf は `present_files` で渡す。

## 修正依頼への対応

「7章はいらない」「ToDo表を足して」のような依頼が続くことが多い。content.json を編集して作り直す。

セクションを削ったら**番号を振り直し**、本文中に「7章のとおり」のような参照が残っていないか確認する。作り直したら手順4のレイアウト確認をもう一度やる。1ページ減ったときに末尾が不格好になりやすい。
